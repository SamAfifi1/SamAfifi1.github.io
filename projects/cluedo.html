Entropy Cluedo Agent

A Cluedo-playing agent that picks suggestions using information theory. Candidate suggestions are ranked by entropy (expected reduction in uncertainty about the hidden cards).

Deductive inference using constraint propagation techniques is used to combine partial information into a coherent game state. The agent was tested against four weaker agents over thousands of simulated games.

What I built

A game engine

A deterministic four-player Cluedo simulator using a balanced 15-card set (5 suspects, weapons & rooms).

Five agents of increasing strength

  • Random
  • Heuristic (suggests unseen cards)
  • Deductive (adds inference)
  • Disjunctive (adds "has at least one of A, B or C" constraints)
  • Entropy agent scores candidate suggestions on entropy.

An experiment framework

A three-tier tournament (self-play, 2v2 head-to-head, 1v3 champion-vs-field) run for 1,000 games per configuration, with an analysis pipeline that generates the results below.

Skills demonstrated

Reasoning under uncertainty

  • Information theory: Expected information gain used to choose actions.
  • Constraint propagation: Deduction by combining partial, indirect evidence.
  • Probabilistic reasoning: evaluating possible game states based on current information.

Optimisation

  • Symmetry reduction: grouped interchangeable cards so far fewer cases need evaluating.
  • Efficient constraint propagation: replaced python's constraint library with a custom matrix and game specific propagation logic

Experimental design and analysis

  • Controlled experiments: Designed 35 matchups with 1,000 games per matchup, rotating player seats and balancing card sets to minimise experimental bias.
  • Data-driven analysis: Built a pandas pipeline to process and analyse game results, comparing win rates and performance across matchups

Challenges and decisions

  • Replacing the constraint library. The python-constraint library was too slow: single turns on scaled-down games took minutes. I wrote a custom matrix representation with Cluedo-specific propagation rules, bringing the inference agents to around 0.002 ms per turn and making large simulations feasible.
  • Making entropy tractable. Symmetry reduction through equivalence classes based on information profiles of suggestions. (cards/suggestions with equal probilities are interchangeable)
  • Fair experiments and removing bias Used a balanced 15-card set to remove the advantage given by having more rooms, seat rotation to remove first-turn advantage, and progressive opponent types so results weren't inflated by beating weak baselines.

Technical detail

How it fits together

The project separates game simulation, agent decision-making and performance analysis. An experiment driver runs batches of games, rotating player positions to reduce the effect of turn order. The game engine handles card deals and player interactions, while each agent uses the same interface to observe the game and choose actions. Results are recorded in CSV files and processed by analysis scripts, making it possible to compare agent performance across thousands of simulated games.

Modular agent design

The project implements five agents using a shared base class, separating agent decision-making from the game engine. This common interface makes agents interchangeable, allowing their strategies to be compared within the same environment and without changing underlying game logic.

How the entropy agent works

For each candidate suggestion, the agent evaluates the possible responses given what each player could still hold, and how that response would change the set of solutions still consistent with its knowledge. It then selects the suggestion expected to reduce the remaining uncertainty the most, leading to the fastest average convergence to a solution.

Checking every possible arrangement of the hidden cards is too slow to be practical, so I grouped cards with identical information profiles into equivalence classes. Two cards are interchangeable if the agent has learned exactly the same things about both, as the inherent value of learning any individual card is equal. The agent can then score one card per group instead of every card.

This is a large saving early in the game, when most cards look identical (no or limited information), and it brought entropy turns from tens of seconds down to approx. 80ms on average. whilst this effect is reduced later in the game, when there are more discrete information profiles, the reduction in state space caused by known information and constraint propagation mitigates this by reducing the overall search space (speeding up the time taken to evaluate each suggestion).

3. One agent against three opponents

Win rate of each disjunctive agent in a game of 1 entropy and 3 disjunctive agents, by seat relative to the entropy agent.

The agent sitting directly after the entropy agent wins 29.2% of games, against about 20% for the other two seats, and the chance of a gap this large arising by luck is below 1 in 100,000. My explanation is that suggestions are partly public: an opponent who acts straight after can use what the entropy agent has just revealed, and accuse first. In 2v2 games a disjunctive agent always sits right after an entropy agent, which probably blunts its advantage there. I haven't tested this directly, so I treat it as a hypothesis.

What I found, and what I'd do next

If the entropy agent chooses more informative suggestions, why doesn't its edge show up as clearly in 2v2 games? My hypothesis is that suggestions are semi-public: other agents learn from them too, so in information-rich games the quality of inference matters more than the quality of suggestions. The seat-order data supports this. When the entropy agent faced three disjunctive agents, the one sitting immediately after it won 29.2% of games, against 19.2% nd 20.5% for the other two seats. That gap is very unlikely to be chance (p < 0.001).

  • The entropy agent is tens of thousands of times slower per turn than the other inference agents, so it may not be worth it for real-time play, and exhaustive enumeration won't scale to bigger games.
  • Next steps: sample worlds rather than enumerating all of them, move the heavy enumeration into a compiled language, and try risk-aware or game-theoretic suggestions that gain information without leaking it to opponents.
