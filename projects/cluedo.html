Entropy Cluedo Agent

A Cluedo-playing AI that picks each suggestion by how many bits of uncertainty it expects to remove, tested against four weaker agents over thousands of simulated games.

The problem

Cluedo is a game of hidden information: you have to work out the three cards in the envelope from the limited feedback you get when other players answer your suggestions. Existing Cluedo AI is good at inference (ruling out impossible card layouts), but usually picks which suggestion to make with simple rules, such as only suggesting cards it hasn't seen. Some suggestions teach you far more than others. This project asks whether choosing suggestions by expected information gain makes an agent play better.

What I built

A game engine

A deterministic four-player Cluedo simulator using a balanced 15-card set (5 suspects, 5 weapons, 5 rooms) to remove the advantage that standard Cluedo's extra rooms give. Agents plug in through a shared abstract base class, so any agent can be swapped into any game.

Five agents of increasing strength

Random, Heuristic (only suggests unseen cards), Deductive (adds inference), Disjunctive (adds "has at least one of A, B or C" constraints) and the Entropy agent, which scores every candidate suggestion.

An experiment framework

A three-tier tournament (self-play, 2v2 head-to-head, 1v3 champion-vs-field) run for 1,000 games per configuration, with an analysis pipeline that generates the results below.

How it fits together

The engine owns all the rules and the hidden cards. Agents only ever see what a real player would: who couldn't answer a suggestion, who showed a card to whom, and, for everyone else, that a player holds at least one of the three suggested cards. Every agent inherits from one abstract base class, so any mix of agents can be dropped into any game without touching the engine.

How the entropy agent works

The agent keeps track of which cards each player could hold, and enumerates every card layout still consistent with what it has seen. For each candidate suggestion it then calculates the mutual information between the envelope's contents and the response it expects (who refutes it, and with which card). That is the expected number of bits of envelope uncertainty the suggestion will remove, and the agent plays the highest-scoring one.

Enumerating every layout is too slow to be practical, so I grouped cards with identical "information profiles" into equivalence classes (cards that are interchangeable given what is known). The agent enumerates and scores at the class level instead of the card level. This is a large saving early in the game, when most cards are equivalent, and it brought entropy turns from tens of seconds down to about 80 ms on average (the slowest self-play turn was 1.9 s).

def _card_fingerprint(self, card):
    column = tuple(self.can_have[loc][card]
                   for loc in range(GameConfig.N_PLAYERS + 1))
    in_constraints = tuple(
        i for i, (loc, cards) in enumerate(self.constraints)
        if card in cards)
    return (column, in_constraints)

Two cards with the same fingerprint are interchangeable, so only one needs evaluating.

Entropy or Disjunctive win rate with 95% confidence intervals. With four players, an even share would be 25%.

Random and heuristic agents lose to every inference agent in 99 to 100% of games. The entropy agent finds the solution fastest, and in 1v3 it beats the disjunctive agent's result against the same opponents (50.2% against 42.7% versus three deductive agents, with non-overlapping confidence intervals). Against three disjunctive agents it still wins 31.1%, above its 25% share. In 2v2 games, though, its 51.5% against the disjunctive agent could easily be chance (p = 0.36), so I treat that matchup as inconclusive rather than a win.

Challenges and decisions

  • Replacing the constraint library. The python-constraint library was too slow: single turns on scaled-down games took minutes. I wrote a custom matrix representation with Cluedo-specific propagation rules, bringing the inference agents to around 0.002 ms per turn and making large simulations feasible.
  • Making entropy tractable. Symmetry reduction through equivalence classes, plus restricting candidate suggestions to cards that could still be in the envelope, made 1,000-game experiments practical.
  • Fair experiments. The balanced 15-card set, seat rotation to remove first-turn advantage, and several opponent types so results weren't inflated by beating weak baselines.
  • Splitting the methodology. A waterfall approach for the rule-bound engine and an iterative one for the agents, whose performance needed constant experimentation.

What I found, and what I'd do next

If the entropy agent chooses more informative suggestions, why doesn't its edge show up as clearly in 2v2 games? My hypothesis is that suggestions are semi-public: other agents learn from them too, so in information-rich games the quality of inference matters more than the quality of suggestions. The seat-order data supports this. When the entropy agent faced three disjunctive agents, the one sitting immediately after it won 29.2% of games, against 19.2% and 20.5% for the other two seats. That gap is very unlikely to be chance (p < 0.001).

  • The entropy agent is tens of thousands of times slower per turn than the other inference agents, so it may not be worth it for real-time play, and exhaustive enumeration won't scale to bigger games.
  • Next steps: sample worlds rather than enumerating all of them, move the heavy enumeration into a compiled language, and try risk-aware or game-theoretic suggestions that gain information without leaking it to opponents.

Skills this shows

Designing and testing AI under uncertainty, applying research ideas (constraint propagation, entropy, symmetry reduction) in working code, profiling and optimising a bottleneck, clean separation of engine and agents with an abstract base class, and running a controlled statistical evaluation and reporting the mixed results honestly.
